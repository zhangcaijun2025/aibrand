# 模型接入点修正 + 设置中心模型智能管理后台 — 设计方案

> 日期：2026-08-10 · 状态：待批准 · 相关：UNIFIED_MODEL_GATEWAY_DESIGN / MODEL_GATEWAY_IMPL_STATE

## 一、现状与问题定位（接入点错误）

统一模型网关后端已全部就绪（42 模型 / 21 ready / 降级链 / 统一计费 / 跨模态工作流），但**前端接入点错位**：

### 1.1 截图识图结论（GLM-4V-Flash 读取用户截图）

用户截图 = **工作台「图片生成」界面**（左栏：工作台/无限画布/我的项目；中间：Agent | 图片生成 | 视频生成 | 视频编辑；右侧：输入框+发送）：

- 中间内容区顶部：当前模型显示为 **"Seedream 5.0 Pro" 固定标签**（非下拉，无可选列表）
- 其右侧：**"1:1 · 1K · 1张"** 参数摘要
- 右下角：**"10积分·不足" + 「去充值」**（余额不足提示）

→ **"模型接入位置" = 工作台图片生成 composer 的模型标签位置**：需要把写死的模型标签换成统一网关模型下拉（可展开选择、置灰未接入、显示单价），并把积分提示接到真实余额与统一提交通道。

| 位置 | 现状 | 问题 |
|------|------|------|
| ✨ 统一生成器抽屉（GenerationWorkshop） | ✅ 已接统一网关 | 入口太深，用户日常不走 |
| 工作台图片生成 composer（WorkbenchStage `.wb-pixpix`） | ❌ 模型为固定标签"Seedream 5.0 Pro"+ 无下拉列表；积分提示"10积分·不足" | **模型接入点错误——应在图片位置（截图所示）** |
| 工作台右侧 AI 面板「模型」参数 | ❌ `genParams.modelName \|\| '待接入'` | 显示"待接入"，未接任何模型 |

结论：统一模型能力应落在**用户实际创作的位置（图片/视频生成 composer + 右侧 AI 面板模型参数）**，而不是单独抽屉。

## 二、接入点修正方案

1. **WorkbenchStage（内容区 composer，图片生成 Tab —— 截图所示位置）**
   - 模型标签 "Seedream 5.0 Pro" → 统一模型下拉（复用 UnifiedModelSelector）：可展开选择、enabled 优先、未接入置灰、显示单次积分
   - 参数摘要 "1:1 · 1K · 1张" 保留，改为随所选模型 capabilities 动态渲染
   - 积分提示 "10积分·不足/去充值" → 接真实余额（`/ledger`）+ 单价（`costCreditsPerCall`），不足时跳转充值
   - 模型数据源：`/workbench/models` → `/api/models/unified/capabilities`
   - 提交通道：`useWorkbenchSubmit`（旧工作流）→ 统一网关 `POST /api/models/unified/generate`
     - 图片：同步返回 URL → 入画布/资产库（保留现有草稿/收藏链路）
     - 视频：queued → 2s 轮询 `/query/{taskId}` → 进度条 → 完成后入画布
   - 降级链 / 计费 / 退款自动生效（后端已有，无需改）
2. **WorkbenchAIPanel（右侧 AI 协作面板）**
   - 「模型：待接入」→ 统一模型下拉（复用 UnifiedModelSelector）
   - 选择后写入 store `genParams`（modelId / modelName / costCreditsPerCall），费用预估改用真实单价 + 余额（`/ledger`）
3. **组件收敛**：`UnifiedModelSelector` 成为唯一模型选择组件，三个位置（composer / AI 面板 / 统一生成器抽屉）同源复用，消除双模型体系
4. **统一生成器抽屉保留**为高级入口（含智能工作流 Tab），与工作台共用同一数据源

### 3.2 模型管理表功能

| 能力 | 实现 | 后端 |
|------|------|------|
| 启用/禁用开关 | 行内 toggle，即时生效 | `PATCH /config`（已有） |
| 单价编辑 | 行内数字输入 | 新增 `PATCH /admin/cost` |
| 测试生成 | 小额真实调用，弹窗显示结果图/错误 | `POST /generate`（已有） |
| 密钥状态列 | 绿=已配置 / 灰=待配置 / 红=欠费或失败 | `GET /health`（已有） |
| 搜索/筛选 | 模型名/供应商/模态/状态 | 前端过滤 |

### 3.3 供应商矩阵卡

- 状态点：● 可用（有密钥 + 适配器） / ○ 欠费或限流（错误透出） / ⚪ 待密钥
- 「配置密钥」→ 展开密钥输入（掩码、保存后即时刷新 ready）
- 「检查」→ 对该供应商做一次最小成本探测，返回延迟/错误

## 四、新增/调整后端 API（P6.5 管理面）

| API | 方法 | 说明 |
|------|------|------|
| `/api/models/unified/admin/summary` | GET | 聚合：供应商/模型/可用/今日调用/余额 |
| `/api/models/unified/admin/key` | POST | 保存供应商密钥（admin，加密存储/环境注入） |
| `/api/models/unified/admin/cost` | PATCH | 修改模型单价（写 ModelCatalog + registry 配置） |
| `/api/models/unified/admin/stats` | GET | 调用统计（按模型/供应商，源自 ledger + tasks） |
| `/api/models/unified/health/check` | POST | 真实 provider 探测（最小成本，非配置级） |

已具备无需新增：`GET /capabilities`、`GET /health`、`PATCH /config`、`GET /ledger`、`POST /generate`、`POST /workflow/run`。
