# ADR-010: R17-R22 后端跨项目收敛决策（智创中心）

> 日期：2026-08-21 ｜ 依据：aibrand-backend（Nx 工作区）+ aibrand-studio 源码直接调研
> 关联：《平台现状盘点与重复性分析.md》R17-R22（后端审计新增）

---

## R17 — content-engine 与 core/creation 去留

**现状**：
- `libs/content-engine/`：完整 Dify 采访 Agent 引擎（ContentEngineService 智能路由/动态采访/Brief 管理 + BrandKnowledgeService），依赖 DifyService/N8nService，**未在任何 app 接线**（app.module 无 ContentEngineModule.forRoot）
- `apps/aibrand-server/src/core/creation/`：仅 `creation.dto.ts` + `creation.schema.ts` 脚手架，**未入 app.module**

**决策**：**content-engine 保留、不接线**（作智创中心采编上游的可选增强，与 intent-parser 的「意图解析」不同层：采编=提问引导出 brief，意图=自然语言→结构化参数；当前 studio 意图链路已自足，无需后端）；**core/creation 脚手架删除**（仅 schema 无逻辑，属半成品）。

**理由**：content-engine 是有价值的完整模块，删除可惜；creation 脚手架无实现无消费，保留是死代码。收敛 = 删死代码 + 保留活资产 + 边界注释。

## R18 — 质检阈值口径

**现状**：
- 后端 `one-api.service.ts diagnose()`：LLM 5 维评分（0-100），`quality-check.step.ts` 用 **≥70 通过**
- studio `quality/standards.ts`：各维度阈值 60-90，**总体通过线 `finalScore >= 70`**

**决策**：**口径已一致（均 ≥70）**，无需改码。确认：后端 diagnose = LLM 质检权威（服务端内容质检）；studio 7 维 QA = 智创中心图片质检权威（视觉）；两者领域不同（文本 vs 图像），阈值统一为 70。

---

## R19 — 两套模型注册表

**现状**：
- 后端 `core/model/`：MongoDB ModelConfig（claude-opus/sonnet/haiku + deepseek-r1/v3，静态 tier/rpm/cost）
- studio `model-gateway/`：代码注册表 46 模型（seedream/qwen/comfy-sd15/minimax-h3 等，动态能力画像）

**决策**：**短期保留两端**（后端模型表服务后端 agent/workflow 内部调度；studio 网关服务前端生成入口）。**长期收敛方向**：studio 网关为唯一生成执行通道，后端模型表降级为「后端内部 LLM 路由配置」。当前不改码，标注边界。

---

## R20 — n8n 模板格式

**现状**：
- 后端 `core/geo/geo-n8n-templates.ts`：TS 对象定义 4 个 GEO 工作流，`exportN8nTemplates()` 仅返回元数据（非可导入 JSON），**无消费方**
- studio `n8n/workflows/*.json`：可导入 JSON 文件

**决策**：**统一格式约定 = 可导入 JSON**（studio 为标准）。`geo-n8n-templates.ts` 标注为「元数据视图」（供后端展示），实际 n8n 导入用 JSON 文件；其 `exportN8nTemplates` 补充导出完整 JSON 的能力或标注不用于导入。

---

## R21 — 两套步骤执行引擎

**现状**：
- 后端 `core/workflow/engine/executor.ts`：递归步骤执行器（WorkflowContext + 重试/跳转/SSE）
- studio `creation/dag/engine.ts`：拓扑 DAG 执行器（多模态创作节点）

**决策**：**分工明确**：后端 executor 承接「服务端内容工作流」（内容生成流水线、质检、发布）；studio DAG 承接「多模态创作编排」（文生图/图生视频等，需调 studio 网关）。不合并（领域不同），标注边界。

---

## R22 — 后端 Claude-Agent 执行器 vs studio planners

**现状**：
- 后端 `core/agent/agent-chat.service.ts`：Claude-Agent 对话执行（agent-registry + evolution）
- studio `creation/planners/`：创作流程角色函数（planSteps/optimizePrompt/pickModel，R14 已更名澄清非 LLM Agent）

**决策**：**保留后端为重型执行者**（需 LLM 多轮/记忆/工具调用时走后端 agent API）；studio planners 保持确定性函数（创作步骤规划），两者职责不同层。智创中心规划 → 调后端 agent API 的桥接**留待 P4 统一网关**，当前标注边界。
